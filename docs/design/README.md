# Runout designs

Direction D · Pulse, design system v1.1. Spec: [DESIGN.md](../DESIGN.md).

| Folder | What | Use it for |
|---|---|---|
| [`prototype/`](prototype/) | Clickable prototype of every screen and state, driven by one mock dataset | The reference M2 builds from |
| [`screens/`](screens/) | Screenshots of every screen and key state, taken from the prototype | Quick review without running anything |
| `canvas-archive/` | The earlier design-canvas boards (`.dc.html`) | History only; superseded by the prototype |

## Run the prototype

```bash
python -m http.server 8765 --directory "docs/design/prototype"
# open http://127.0.0.1:8765
```

The **Prototype controls** panel (bottom right) switches:
- **Release:** MVP, R2 or R3. Navigation and features change to match each release.
- **State:** normal, empty, loading, offline or error, for the current screen.
- **Quick add test links:** new, duplicate, episode and short link.
- **Screen:** jump to any screen.

The prototype loads Google Fonts for convenience. The app itself self-hosts its fonts (TSD §7).

Keyboard shortcuts work as specified:
- `Ctrl+N`: quick add.
- `Ctrl+K`: search.
- `1` to `5`: set status on an item page.
- Arrow keys: rating.
- `Esc`: close a dialog.

## Mock data

`prototype/mock-data.json` (and `mock-data.js` for the browser) is generated by `python scripts/gen_mock_data.py`. It's deterministic (fixed seed) and shaped like TSD §3. Contents:

| Data | Amount |
|---|---|
| Records | 65 (16 artists, 33 albums, 16 tracks) |
| Status history | Full history per record |
| Phone captures waiting for a name | 2 |
| Listening events | About 5,600 over 12 months, from the desktop log and the export (generator asserts that counts agree everywhere) |
| Precomputed insights | Charts per range, monthly hours, weekday × hour heatmap, unfinished albums, your-take items, year in review |
| Playlists | 6, with duplicates and low ratings |
| Spotify-provided lists | Top items and recent plays (source A, kept separate) |
| Settings and usage counters | Included |

Every screen reads the same data, so counts, statuses and dates agree everywhere. M2 reuses the same file for `src/mocks/`. Spotify IDs are random; there are no real export values.

## Journey walkthroughs (BRD §8)

Follow these in the prototype. Set **Release** in the controls panel as noted.

| Journey | Release | Steps |
|---|---|---|
| A. Save music for later | MVP | Home: paste a link in the top field and press Add → Quick add shows the embed and the suggested name → Save → toast with Undo → the item appears in Backlog under its priority |
| B. Capture from phone | MVP | Settings: Shortcut steps → (share on the iPhone) → Home: “Waiting for a name” → Name it → Quick add in naming mode → Save → Backlog |
| C. Explore and document an album | MVP | Backlog: Start on an album → Item detail: status In progress → Open Spotify → back in Runout: rating (click or arrow keys), tags, review → status Explored or Not for me, optional Revisit flag → History shows each change |
| D. Explore an artist | MVP | Quick add with an artist link → Item detail (artist): why this artist → “In your library” list, Add to backlog per record → set the artist’s status |
| E. Rediscover | MVP | Rediscover: filter by tag, rating or Revisit only, or pick a saved filter → open a record → Open Spotify; optionally update notes |
| F. Review listening history | R2 | Settings: Import an export → Import step 1 to 3 → Insights (Listening, Collection, Your take, Year in review), freshness line on every card → Recent plays: rate or save plays |
| G. Clean up a playlist | R3 | Playlists: Check-up shows duplicates and low ratings → Open in Studio → Keep or Cut per track → Apply → confirm dialog → toast, then “Undo last apply” banner |
| H. Back up and restore | MVP | Settings: Back up now (toast with location and size) → Restore → pick a backup → check runs → restored with verified record count; set the state to Error to see a failed check |

`screens/states/` holds `<screen>-loading|empty|offline|error.png` for 13 screens (home, home-mvp, backlog, library, search, detail, rediscover, plays, insights, import, playlists-studio, from-spotify, settings). The empty MVP home is the first-run screen, so it is `SC-02b-first-run.png` rather than a state file. Import loading and empty are captured on steps 2 and 3; the From Spotify error state is the expired connection (sign in again).

To regenerate every screenshot, serve the prototype (see above) and run `scripts/capture_designs.js` with the Playwright MCP tool `browser_run_code_unsafe`. It first renders every screen × state × release and every dialog, and fails if anything throws or shows leftover text.

More states can be reached in the prototype than were captured. Each one can be opened by choosing a screen and a state in the controls panel:
- Quick add also covers naming a phone capture and the title still loading.
- The Spotify connection steps (waiting, success, failure) and the restore check (in progress, failed) can be stepped through.
- Delete confirmations, Make a Spotify playlist, New shelf, Save filter, and Tag rename and merge each open as dialogs.

Dashed “Spotify embed” and “Spotify logo” boxes are placeholders. The app uses the real embed iframe and the official logo file.
